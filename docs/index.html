The Robot Intern

How a volunteer-run alumni chapter uses an AI assistant to publish events, build the newsletter, and answer the inbox — without letting it speak for us.

A look at what we actually automated, what we refused to, and what broke along the way
The problem

One event. Six places to put it.

Every JETAASC event has to reach people in more than one spot, and none of those spots talk to each other.

A single Nihongo Dake Dinner goes on the Wix site, the Google Calendar, Discord, Partiful for RSVPs, the monthly newsletter, and sometimes Facebook. Each one wants the description written a little differently. Each one wants the flyer in a slightly different format. Miss one and half the chapter never hears about it.

Multiply that by a few events a month, plus a newsletter, plus everyone who writes in asking how to get involved. All of it done by volunteers with day jobs.

With the assistant

The work that disappeared is the copying, resizing, reformatting, and remembering. The work that stayed is deciding what we actually want to say.

How it works

We wrote down how we do things. Once.

There's no clever trick here. The assistant is useful because our process stopped living in one person's head.

1

Write the routine down in plain English

What a Boba Banter announcement should sound like. Where the flyers live. Which deadline the newsletter runs on. The stuff a new board member would have to be told.

2

The assistant reads it before it acts

Instead of guessing, it follows the routine we already agreed on. Same tone, same format, same steps, whoever is at the keyboard.

3

A human reads the draft

Nothing is published or emailed until someone on the board looks at it and says go.

4

When something goes wrong, we fix the routine

The fix gets written back down, so the same mistake doesn't come back next month. That's the whole loop.

The value isn't that a computer writes our newsletter. It's that we finally had to write down how we run this chapter.

The unexpected part
The rules

What it is not allowed to do

A chapter's credibility is its mailing list and its word. These rules are written into the instructions themselves, not just remembered.

Never send.Email is drafted and left sitting in Gmail. A person presses send, every time.
Never invent.No date, venue, or price it didn't read somewhere real. Unknowns stay marked TBA rather than getting filled in with something plausible.
Never promise.It can't offer anyone a speaking slot, a role, or a commitment on the board's behalf.
Test where nobody's watching.Anything new gets tried in a private admin channel first, never in a room members can see.
Show your work.Every judgment call and assumption gets surfaced, so the board can overrule it before it ships.
A real example

The September newsletter

This one is worth telling because it didn't work the first time.

The plan was simple: board members fill in a shared Google Doc all month, then the assistant turns that doc into the Mailchimp email in one shot.

It kept failing on the flyers. Someone would paste an event flyer into the doc, and the assistant would read the doc and see only text, as if the image wasn't there. Two people looking at the same document, one of them unable to see half of it.

The cause turned out to be boring: the normal way of reading a Google Doc hands back the words and only a reference to each picture, not the picture itself. Asking for the document a different way — the way you'd use to download it — returns the images too.

That fix is now written into the routine, along with the size limit we discovered while testing (Google quietly shrinks anything larger than about 2000 pixels). September's issue was built start to finish from its doc: banner, both flyers, all the copy, one pass.

Half of what we automated, we only understood after watching it fail.

Every fix in this project started as a bug
Honestly

Where it helps, where it doesn't

Genuinely good at

  • The same task across five platforms that each want it formatted differently
  • Remembering the deadline, the naming convention, the folder, the credit line
  • First drafts that a human then makes sound human
  • Tedious cleanup nobody volunteers for, like archiving old events

Still on us

  • Deciding what events are worth running
  • Knowing that a returning JET needs a warm reply, not an efficient one
  • Catching the thing that is technically correct and completely wrong in tone
  • Anything that depends on knowing the people involved

It is a very fast, very literal intern who has read every one of our procedures and has no judgment about what matters. Useful in proportion to how clearly you explain what you want. Which, it turns out, is also true of running a volunteer board.
